# AGENTS.md

This file provides guidance to Codex (Codex.ai/code) when working with code in this repository. It mirrors `CLAUDE.md`; keep the two in step.

## Repository layout

Two independent halves of one product (plus a companion app for the PC), a battery-powered RFID attendance logger that shows its log to a PC as a USB drive: a read-only `ATTEND.CSV` and `LECTURES.CSV`, a `LECTURES` folder with one CSV per lecture, a `STATUS.TXT`, a `LASTCARD.TXT` (the card just tapped, for registering it at the PC), and a `SETTINGS.CSV` the PC edits to set the clock, start a lecture or clear the log. The device keeps no list of registered cards: it records every card, and the PC app decides who is registered. It reads ISO14443-A cards (MIFARE Classic, NTAG and the like) with an ST25R3916 13.56 MHz NFC reader. Earlier firmware targeted a 125 kHz EM4100 front end; that code is gone:

- `Firmware/` is for the **STM32L432KBU6** (Cortex-M4F, 128 kB flash shared by the code and the log). It is an STM32CubeIDE project and also has a standalone Makefile.
- `Companion/` is the PC app, one Qt window: `attendance_qt.py` (PySide6, from `requirements.txt`, installed into `Companion/.venv`, which is gitignored), launched by `start.sh` / `start.bat`; without PySide6 it says how to install it and exits. Its non-GUI helpers are in `app_helpers.py`; `attendance_app.py` finds the device drive and holds the actions (`python attendance_app.py` just opens the window); `attendance_db.py` holds the SQLite database; `report_pages.py` the reports and a standard-library PDF writer. See the Companion section below and `Companion/README.md`.
- `PCB/` is a KiCad 10 project (schematic and routed board; see the PCB section). The root sheet `Attendance Management System.kicad_sch` has three hierarchical sheets: `power.kicad_sch`, `mcu.kicad_sch` and `rfid.kicad_sch`. These are S-expression files that KiCad writes. Don't hand-edit them unless asked. `.history/` and `*.lck` are generated by KiCad and gitignored.

`Firmware/docs/ARCHITECTURE.md` is the design document. It covers polling mode and the plan for interrupts, data formats, card reading, lecture sessions, the USB volume and `SETTINGS.CSV`, the LED/motor patterns, the `dbg_*` live-debug globals, which part of the code handles each step of the flow chart, board requirements, and the known limitations found in review. Read it before any non-trivial firmware change. `Firmware/docs/USER_GUIDE.md` is for the people who run a class with the device.

## Commands

Run these from `Firmware/`:

```sh
make test    # builds and runs the host tests for Level 2 (plain cc, no ARM toolchain needed)
make         # cross-compiles to build/card-attendance.{elf,hex,bin} and prints memory usage
make clean   # removes build/ and the test binary
```

- `make` uses the GCC that ships with STM32CubeIDE under `/opt/st/stm32cubeide_*/…/tools/bin` when one is installed. Otherwise it falls back to `arm-none-eabi-` on `PATH`.
- The Makefile has no flash or debug target. Flashing and debugging go through STM32CubeIDE. Its build output goes to `Debug/`, which is gitignored.
- `Companion/` has no automated tests (they were removed with the browser version; `Companion/tests/` and `Companion/web/` are gitignored). Check a change by running the window, `python attendance_qt.py --demo` (made-up data, no device), or by pointing it at a dumped volume with `--device-dir` (`Tests/vol_image dump`, then extract the image with `7z x`).
- `Tests/fs_check.sh` is an optional extra that needs `mtools` and `dosfstools`. It dumps the USB volume to a disk image, lets `fsck.fat` and `mcopy` judge it and copy a new `SETTINGS.CSV` over it, then plays the changed sectors back into the firmware. Run it after any change to `fat12.c`, `usb_storage.c`, `device_cfg.c` or `settings_file.c`. Without `mtools`, `vol_image dump` plus `fsck.fat -n -l` (which lists the long names) and `7z x` cover most of it.
- All firmware tests (927 checks) build into one binary, `Tests/run_tests`, from every `App/Src/*.c`, `Tests/host_platform.c` and every `Tests/test_*.c`. Each test group is a `test_*()` function, defined in one of those files (`test_main.c`, `test_fsm.c` (including `test_fsm_plugged_in()`: eject, button, `#CLEARLOG`, and `test_fsm_lectures()`: lectures started from the button, `test_fsm_wakeup()`: the reader's wake-up mode, `test_fsm_sleep()`: the deadlines the loop sleeps to, `test_fsm_double_press()` and `test_fsm_wake_learning()`: the wake-up offset and window learning), `test_cards.c` (no card list, `LASTCARD.TXT`, the `LECTURES` folder), `test_session.c`, `test_settings.c`, `test_hostfs.c`) and called from `main()` in `Tests/test_main.c`. There's no command-line filter, so to run a single group, comment out the other calls in `main()`. The `CHECK()` macro (`test_util.h`) prints `FAIL file:line` for each failure, and the binary exits non-zero if any check fails. `Tests/vol_image.c` and `Tests/parse_settings.c` are separate host tools (`vol_image` for `fs_check.sh`), not part of `run_tests`. `test_hostfs.c` is a small FAT host the tests read the volume through, including subfolders and long names (`hf_list()`).
- Warnings are the only lint. `App/` gets extra flags in the cross build (`-Wconversion -Wsign-conversion -Wshadow -Wundef`). The host build is stricter still (`-std=c11 -Wpedantic`, where the cross build uses gnu11), so `App/` code must compile warning-free under both.

Run these from `PCB/` with `kicad-cli` (KiCad 10). Write the reports outside the repo:

```sh
kicad-cli sch export netlist --format kicadsexpr "Attendance Management System.kicad_sch" -o /tmp/ams.net
kicad-cli sch export bom "Attendance Management System.kicad_sch" -o /tmp/ams-bom.csv
kicad-cli sch erc "Attendance Management System.kicad_sch" -o /tmp/erc.rpt
kicad-cli pcb drc "Attendance Management System.kicad_pcb" --schematic-parity -o /tmp/drc.rpt
```

The netlist is the quickest way to see which pin is on which net. The `.kicad_sch` files are hard to read directly.

## Firmware architecture: "Level 2 decides, Level 1 acts"

- **`App/` (Level 2)** holds all the logic and arithmetic. It must include no HAL, CMSIS, vendor or register headers, and it compiles and runs on a workstation. If a host test build ever needs an STM32 header, the layering is broken.
- **`Bsp/` (Level 1)** holds the HAL drivers. They implement `App/Inc/platform_if.h`, the contract that Level 2 declares. Level 1 hands up only raw values (ADC counts together with `VREFINT_CAL`, the bytes a card sent, raw button and VBUS levels, RTC calendar fields, 512-byte sector requests) and makes no decisions. All conversion happens in `App/` (`battery.c`, `iso14443a.c`, `card_reader.c`, `button.c`, `timeutil.c`, `usb_storage.c`).
- **Main loop and sleep:** the main loop runs `bsp_init()`, then `app_init()`, then repeats `app_task()`. Each pass samples the button and VBUS, steps the LED/motor pattern, runs the reader, runs the timers, handles the events those posted, publishes the `dbg_*` globals, then computes the soonest deadline (`next_wake()` in `app_fsm.c`: pattern step, heartbeat edge, `btn_next_ms()`, VBUS debounce, `cr_next_ms()`, battery sample, flush, inactivity, capped at `APP_SLEEP_MAX_MS`) and calls `plat_sleep_until(wake, deep, pred)`. In `ST_IDLE` (`deep`) a sleep of at least `BSP_STOP2_MIN_MS` is Stop 2: LPTIM1 free-runs on the LSE (16-bit, 32768 Hz, compare and wrap interrupts, EXTI line 32), wakes the part at the deadline (at most `BSP_STOP2_MAX_MS` = 1.9 s per sleep), and `stop2_for()` in `bsp_power.c` adds the ticks slept to HAL's `uwTick`, carrying the fraction, so `plat_uptime_ms()` (still `HAL_GetTick()`) never notices. USB sessions and shutdown keep 1 ms Sleep-mode passes. Interrupts: SysTick, USB, LPTIM1, EXTI0 (button) and EXTI9 (VBUS) on both edges, and EXTI1 (the reader's wake-up). The button/VBUS ISR only posts `APP_EVT_INPUT_EDGE`, once per sleep (`bsp_input_edge()`); the loop samples and debounces the levels as before, and `plat_sleep_until()` also refuses to sleep when a level differs from the one the loop last read (`bsp_input_changed()`). `BSP_ENABLE_STOP2` = 0 goes back to Sleep mode only. Every LPTIM1 register wait is bounded (`BSP_LPTIM_WAIT_LOOPS`): if the LSE is not running, `dbg_lptim_fault` says why and the loop sleeps in Sleep mode only instead of hanging (it used to spin for ever, with interrupts masked inside `stop2_for()`). `Error_Handler()` (in `main.c`'s user block) fast-blinks the red LED with registers only, so a start-up failure, most likely the LSE not starting, is visible instead of a silent dead unit. The host stub always advances 1 ms and records what was asked (`host_sleep_wake`, `host_sleep_deep`).
- **Card detection (`APP_NFC_USE_WAKEUP`, on by default):** while the field is empty the ST25R3916 sits in its wake-up mode: it measures the antenna amplitude on its own timer every `APP_NFC_WAKE_PERIOD_MS` and raises PB1 when a reading strays more than the window (`delta`) from a reference; every other chip interrupt is masked in wake-up mode (an unmasked I_osc fired every measurement: 99 % false wake-ups on the bench). EXTI1 posts `APP_EVT_NFC_WAKE` (one shot, line masked in the handler) and `cr_wake()` switches to the 100 ms poll until 3 empty polls, then re-arms with a fresh reference. It arms only straight after an empty poll, so a card is never measured into the reference. The chip takes no commands in wake-up mode: `cr_enable(false)` leaves it first, which `sample_battery()` does before a supply-mode change. The reference is corrected by a learned `offset` (the chip's wake-up reading, register 0x36, minus Measure amplitude, learned from false wake-ups) and the window widens on repeated false wake-ups (`APP_NFC_WAKE_DELTA_MIN`..`MAX`). `dbg_nfc_armed`, `dbg_nfc_wakeups`, `dbg_nfc_false_wakes`, `dbg_nfc_wake_irq` (should be 0x040000), `dbg_nfc_wake_raw`, `dbg_nfc_wake_offset` and `dbg_nfc_wake_delta` show it working. To read globals with a hot-plugged probe, halt for the read (`STM32_Programmer_CLI -c port=SWD mode=HOTPLUG shared -halt -u <addr> <len> f.bin -run`); unhalted reads come back as zeros while the core sleeps. Every SWD flash toggles `FLASH_SR.PEMPTY` (measured: ST's flash loader clears status flags with a mask that includes it, and writing 1 flips it); while it is set, every reset but a power-on boots the system bootloader (DFU, 0483:df11). `bsp_early_init()`, the first call in `main()`, sets `SCB->VTOR = FLASH_BASE` and flips a set PEMPTY back (`dbg_pempty_cleared`), so any debug session fixes it; after a flash plus immediate reset that lands in DFU, power-cycle, flash once more, or write 0x00020000 to `FLASH_SR` (0x40022010) and reset. Set `APP_NFC_USE_WAKEUP` to 0 for plain polling.
- **Event flow:** polled sources post the same events an ISR would, into `app_events.c`, so moving a source to an interrupt means posting from its ISR instead. The only Level 2 symbol that Level 1 may call is `app_event_post()`, from interrupt context (the USB storage callback, the EXTI1 reader wake-up and the button/VBUS edges do).
- **Deciding where a constant goes:** policy values go in `App/Inc/app_config.h`. Hardware facts such as pins, timer instances, clocks and antenna parameters go in `Bsp/Inc/bsp_board.h`, which also holds the full pin map.
- **Adding a platform function** takes three steps: declare it in `platform_if.h`, implement it in `Bsp/Src/`, and add a stub to `Tests/host_platform.c`. The stub is required because the host build compiles every `App/Src/*.c`, `app_fsm.c` included, so a missing stub fails at link time. The stub platform backs flash with RAM and can inject write failures (`host_write_failures`).
- Level 2 modules own no hidden static buffers when they can avoid it: `card_reader_t`, `button_t`, `feedback_t` and friends are caller-owned structs, which is what lets the tests run several instances.
- **Live debugging:** the `dbg_*` globals for STM32CubeIDE Live Expressions (battery mV and `dbg_battery_percent`, last card UID/ID, scan result, button counts, reader status and wake-up counts, record counts, `dbg_sleep_ms`, RTC) are defined in `Core/Src/main.c`, in the `USER CODE BEGIN PV` block, and declared in `App/Inc/app_debug.h`. `Tests/host_platform.c` defines its own copies, so a new one goes in all three places. Writing `dbg_set_time` and then `dbg_set_time_request = 1` sets the RTC. While a debugger is attached, `plat_sleep_until()` returns at once (no Sleep, no Stop 2) so Live Expressions reads stay stable; test Stop 2 without the debugger.

### Timing and power rules

- Nothing blocks. Don't use `HAL_Delay` or busy-waits in app code. Every timer is a timestamp compared against `plat_uptime_ms()` with wrap-safe subtraction, including the reader's 5 ms field guard. Feedback patterns are tables of (output mask, duration) pairs, stepped against the uptime.
- The reader polls every 100 ms with the field on only for the poll (in wake-up mode, only between a wake-up and the field going empty again), and pauses while a feedback pattern plays, leaving wake-up mode too, so the motor never runs with the field on.
- `plat_sleep_until()` takes an "am I still idle?" predicate and re-tests it, and the input levels, with interrupts masked just before WFI. That closes the race between the queue check and going to sleep. A new timer in Level 2 must be added to `next_wake()`, or the loop can sleep through it (up to 1 s).
- Standby is entered only after the button is released; the ST25R3916 runs straight off the cell, so `plat_nfc_power_down()` must run first.
- The core runs at 4 MHz from MSI with the PLL off. USB sessions raise it to 24 MHz, with HSI48 trimmed by the CRS (the board has no USB crystal). `HAL_RCC_ClockConfig()` re-derives SysTick, so the uptime stays in milliseconds. Stop 2 wakes on MSI at the range it had (`STOPWUCK` = MSI), which is the scanning clock.

## MCU pin map (STM32L432KBUx, UFQFPN32)

The card reader is an **ST25R3916** 13.56 MHz NFC reader on SPI1, driven by `Bsp/Src/bsp_nfc.c`. The table below comes from `Firmware/Card Attendance System.ioc`, which was updated for the ST25R3916 on 2026-09-25. Two places where the `.ioc` and the firmware differ:

- The `.ioc` declares PA0, PA9, PB1 and PB6 as EXTI inputs. `bsp_gpio.c` de-initialises them (`HAL_GPIO_Init()` never disarms an EXTI line) and reconfigures PB6 as a plain input and PA0 and PA9 as EXTI on both edges. PB1 goes back on EXTI1 (rising) with the line masked in `EXTI->IMR1`; `bsp_nfc.c` unmasks it only while the reader is in wake-up mode. The handlers are in `bsp_isr.c` (`EXTI0/1/9_5_IRQHandler`, `LPTIM1_IRQHandler`, `HAL_GPIO_EXTI_Callback`), at `BSP_PRIO_NFC` / `BSP_PRIO_INPUT` / `BSP_PRIO_LPTIM`.
- The `.ioc` still enables TIM1 and TIM2 from the EM4100 design. `main.c` initialises them but nothing starts them. `MX_LPTIM1_Init()` sets LPTIM1 up on PCLK; `lptim_init()` in `bsp_time.c` resets it and moves it to the LSE.

All 18 used pins are locked in CubeMX.

| Pin | Label | CubeMX signal / mode | Notes |
|---|---|---|---|
| PC14 | LSE_IN | `RCC_OSC32_IN`, LSE crystal | 32.768 kHz crystal. Required: the RTC, LPTIM1 and LPTIM2 run from it through Stop 2 |
| PC15 | LSE_OUT | `RCC_OSC32_OUT`, LSE crystal | |
| PA0 | PWR_BTN | `GPIO_EXTI0`, falling edge, pull-up | Power button, active low to GND. The BSP arms EXTI0 on both edges to wake the loop. Also WKUP1, the only wake source from Standby. The pull-up is kept in Standby via `PWR_PUCRA` |
| PA2 | LED_GREEN | `GPIO_Output` | Active high |
| PA3 | LED_RED | `GPIO_Output` | Active high |
| PA4 | VIB_EN | `GPIO_Output` | Enables the vibration motor driver, active high |
| PA7 | BATT_SENSE | `ADC1_IN12`, single-ended | Battery through a divider: R7 (4.7 MΩ) over R8 (2.7 MΩ), with C3 (100 nF) across R8. The firmware matches (`APP_BATT_DIV_*_KOHM`). Sampled for 640.5 cycles every 10 s |

- **SPI1 must stay in mode 1** (CPOL 0, CPHA 1), 8-bit, MSB first, with software NSS. The ST25R3916 needs BSS held low for a whole multi-byte transaction. The STM32's hardware NSS can't do that: it either stays low as long as SPI is enabled, or, with NSSP, pulses between bytes (and NSSP is ignored when CPHA is 1). The ST25R3916's limit is 10 MHz. The `.ioc` uses /16, which gives 5 MHz at its 80 MHz SYSCLK, so the BSP has to pick its own prescaler for the clock it actually runs at.
- **Internal channels also enabled:** `ADC1_Vref_Input` (VREFINT), LPTIM1 and LPTIM2 counting their internal clock, the RTC calendar, and SysTick.
- **Other pins:** PA1, PA5, PA6, PA8 and PA10 are spare. The schematic uses PA15 (`PN532_NSS`) and PB6 (`PN532_IRQ`) for the PN532 backup header, but they aren't in the `.ioc` yet. `bsp_gpio.c` first sets every pin to analog, the lowest-leakage state, and then configures only the pins it uses. PH3/BOOT0 is strapped low.
- **Card detection** moves to the ST25R3916's own low-power wake-up. The RFID sheet has CSI/CSO capacitive-sensor pads and no separate touch IC.
- **CubeMX ignores some `.ioc` keys.** Headless `config load` reports them as invalid parameters and falls back to the defaults. They include `RCC.Lptim1ClockSelection`, `Lptim2ClockSelection`, `UsbClockSelection` and `AdcClockSelection`, whose correct names are `LPTIM1CLockSelection`, `LPTIM2CLockSelection`, `CK48CLockSelection` and `ADCCLockSelection`. Also ignored: `LPTIMx.Prescaler`, `RTC.Hour_Format`, `USB.VirtualMode`, and the value of `ADC1.CommonPathInternal`. As a result, CubeMX runs LPTIM1/2 from PCLK and USB from PLLSAI1, and the BSP reprograms both at run time. `stop_unused_oscillators()` in `bsp_clock.c` stops the main PLL and HSI48, but not PLLSAI1.
- **Checking an `.ioc` edit without the GUI:** run headless CubeMX on a scratch copy. The generator is `java -jar …/com.st.stm32cube.common.mx_*/STM32CubeMX.jar -q script.txt`, using the JRE bundled under `…/com.st.stm32cube.ide.jre.*/jre/bin/java`. The script runs `config load`, `project toolchain "STM32CubeIDE"`, `project path`, `project name`, then `project generate`. It needs `~/STM32Cube/Repository/STM32Cube_FW_L4_V1.18.2`. Headless mode rewrites `TargetToolchain` and `UnderRoot` in the saved `.ioc`, so don't copy that file back.
- **Two sets of pin macros:** CubeMX generates `*_Pin` / `*_GPIO_Port` in `Core/Inc/main.h`, but the BSP uses its own `PIN_*` / `PORT_*` from `bsp_board.h`. Moving a pin means updating the `.ioc` (then regenerating), `bsp_board.h`, and `PCB/mcu.kicad_sch`.

## PCB (`PCB/`, KiCad 10)

The board is a two-layer, 1.6 mm design. The root sheet holds three sub-sheets: Power, MCU and RFID.
- Power and MCU are joined by the `D+` and `D-` hierarchical labels.
- RFID connects to the MCU through `NFC_SCK`, `NFC_MISO`, `NFC_MOSI`, `NFC_NSS` and `NFC_IRQ`.

**Library dependencies:** three parts don't come from the stock KiCad libraries. All three use one SnapEDA folder at an absolute path outside the repo, `/home/rajinthan/Documents/kicad/external_libs/Snapeda.pretty`, so a fresh clone can't resolve them. That folder is referenced two ways:
- as `External` in the user's global library table;
- as `Snapeda` in the project's `PCB/fp-lib-table`, which lists the same entry twice.

The parts:
- **U3:** `External:TPS7A0233PDBVR` (symbol) and `External:SOT23_DBV_TEX-L` (footprint).
- **U5 (ST25R3916):** `External:QFN50P500X500X100-33N`. ERC gives a `lib_symbol_mismatch` warning, because the copy embedded in the schematic differs from the library's.
- **AE3 (loop antenna):** `Snapeda:NFC_Loop_40x30_3T`.

Every other part comes from the stock KiCad libraries.

### `rfid.kicad_sch`

- **U5:** ST25R3916-AQWT (QFN-32), in SPI mode because I2C_EN is tied to GND. It was U4 before re-annotation.
- **Supplies:** the reader runs straight from the Li-ion cell, with no load switch, so it is always powered.
  - VDD_TX, decoupled by C21 and C25, is on `BAT+`. So is VDD, through FB2 (600 Ω at 100 MHz).
  - VDD_IO (with C11) and R12, the BSS pull-up, are on `+3V3`, so SPI and IRQ run at the MCU's logic level.
  - Keep that split. Moving VDD_IO to `BAT+` drives 4.2 V into PB0, PB1 and PB4.
- **Decoupling:** the internal regulator pins (VDD_A, VDD_D, VDD_AM, VDD_RF/VDD_DR, AGDC) each have 100 nF plus 1–2.2 µF.
- **Crystal:** Y1 (27.12 MHz, CL 10 pF, 3225 4-pad; YXC X32252712MMB4SI) on XTI/XTO, with C9 and C10 (15 pF).
- **Antenna path:** RFO1/RFO2 go through an EMC filter (L3/L4, 470 nH in 0805, with C12/C13, 150 pF), then the matching network (C16–C19) to the nodes DR1/DR2. R15 (1.5 kΩ) sits across DR1/DR2, and R21/R22 (0 Ω) feed the loop antenna AE3 (`NFC_Loop_40x30_3T`, 40 × 30 mm, 3 turns).
- **RX path:** a capacitive divider on each side, per ST AN5276. DR1 → C37 (10 pF) → RFI1, with C38 (150 pF) to GND. DR2 → C15 (10 pF) → RFI2, with C39 (150 pF) to GND. That's roughly 1/16 of the antenna voltage, which keeps RFI under its 3 Vpp limit. R13, R14 and C14 have been removed.
- **Capacitive sensor:** J6 (on CSI) and J5 (on CSO) are 1×2 mm SMD solder pads for the electrode used by the chip's capacitive wake-up.
- **Unused pins:** MCU_CLK, EXT_LM, AAT_A and AAT_B are not connected.

### `power.kicad_sch`

- **USB input:** J1 is a USB-C receptacle (GCT USB4110, USB 2.0 only). It is set up as a sink with 5.1 kΩ CC pull-downs (R1, R2), and VBUS becomes `+5V`. SBU1 and SBU2 are not connected.
- **USB ESD:** U6 is a USBLC6-2SC6 (SOT-23-6).
  - D+ is on I/O1 (pins 1 and 6), D- is on I/O2 (pins 3 and 4), VBUS is on `+5V`, and pin 2 is GND.
  - On the board, place it next to J1 and route D+/D- straight through its pads.
- **Charger:** U2 is an MCP73833 Li-ion charger, fed from `+5V` and charging `BAT+`.
  - R6 (1 kΩ) on PROG sets about 1 A of charge current (I_REG = 1000 V / R_PROG).
  - TH1, an NTC thermistor, is on THERM.
  - Status LEDs: D1 (red) on STAT1, D2 (green) on STAT2 and D3 (green) on PG, each through 470 Ω. They are powered from `+5V`, so they only light while USB is plugged in.
- **Battery:** J2 is a 2-pin JST-XA connector on `BAT+`.
- **3.3 V supply:** U3 is a TPS7A0233 3.3 V LDO running from `BAT+` to `+3V3`. Its EN is tied to `BAT+`, so it is always on.
- **Bulk capacitors (0805):**
  - C35 (4.7 µF) on `+5V`. Keep the total on VBUS at or below USB's 10 µF limit.
  - C36 (10 µF) on `BAT+`, covering the charger output, the LDO input and the motor.
  - `+3V3` has C2 (4.7 µF), C1 and C3 (100 nF), and C11 (100 nF, at U5's VDD_IO).

### `mcu.kicad_sch`

- **U1:** STM32L432KBUx.
- **Decoupling:** C1 and C3 (100 nF) plus C2 (4.7 µF) on `+3V3`. VDDA is fed through ferrite bead FB1, with C4 (10 nF) and C5 (1 µF).
- **Crystal:** Y2 (32.768 kHz, CL 6 pF, 3.2 × 1.5 mm; Epson FC-135) with C6 and C7 (8.2 pF). No 4 pF crystal comes in this size at LCSC, so the load caps were raised from 4.3 pF on 2026-09-26.
- **Reset and boot:** NRST has C8 (100 nF) and the SW1 reset button. BOOT0 (PH3) has R7 (10 kΩ) pulling it down and the SW2 button pulling it to `+3V3`.
- **Debug:** J3 is a 4-pin SWD header: 3V3, SWDIO, SWCLK and GND. It has no NRST pin.
- **LEDs:** D6 (green) on PA2 and D5 (red) on PA3, each through 470 Ω to GND. They are active high, which matches the firmware.
- **Vibration motor:** the motor plugs into J4, between `BAT+` and the drain of Q1, an AO3400A low-side N-MOSFET. Q1's gate is driven by PA4 (`VIB_EN`) and pulled down by R11 (10 kΩ). D4, an SS14 flyback diode, sits across J4 with its cathode on `BAT+`.
- **Button:** SW3 (`KEY`) switches to GND, with R8 (10 kΩ) pulling it up to `+3V3`.
- **Battery sense:** R7 (4.7 MΩ, from `BAT+`) over R8 (2.7 MΩ), with C3 (100 nF) across R8, feeds both PA7 and PB7 (net `/MCU/BAT_SENSE`). C3 charges through R7 ∥ R8 = 1.7 MΩ, a 171 ms time constant, so a reading right after a battery is connected is low; `APP_BATT_SETTLE_MS` covers that.
- **VBUS sense:** R9 and R10 (4.7 MΩ each) divide `+5V` down to PA9.
- **Reference designators were re-annotated after the notes in this section were written** (the MCU is now U4). Check the netlist rather than trusting the designators here.
- **PN532 backup header:** J7 is a 1×8 2.54 mm socket for a PN532 breakout, pinned for the Elechouse V3's SPI header with the module's DIP switches set to SPI.
  - **Pinout:** 1 SCK, 2 MISO, 3 MOSI, 4 SS, 5 VCC (now `BAT+`), 6 GND, 7 IRQ. Pin 8 (RSTO) has a no-connect flag.
  - **Shared:** SCK, MISO and MOSI, with U5.
  - **Separate:** the PN532 has its own chip-select, `PN532_NSS` on PA15, pulled up by R20 (10 kΩ), and its own IRQ, `PN532_IRQ` on PB6. The two readers' IRQ outputs have opposite polarity and are both push-pull, and a faulty U5 would still drive MISO, so neither line can be shared.
  - **Firmware:** the PN532 uses SPI mode 0, LSB first, at up to 5 MHz, and its IRQ is active low. Reconfigure SPI1 whenever you switch readers. PB6 is EXTI6, which shares the `EXTI9_5_IRQn` vector with PA9 (VBUS).
  - **Power:** VCC is on `BAT+`, so the module's RF current bypasses the 200 mA LDO. This only works if the module makes its own 3.3 V I/O rail; see the open issues.

### Schematic conventions (set 2026-09-25)

- **Power symbols:** use the matching library power symbol for every net: `power:+BATT` with value `BAT+`, plus `power:VDDA`, `power:+5V` and `power:+3V3`. Never use a `+3V3` symbol with its value changed.
- **ERC flags:** `PWR_FLAG`s sit on `+5V` (at C35), `VDDA` (at C5) and the ST25R3916's `DC1` (VDD after FB2).
- **Edited embedded symbols:** three pins were fixed in the schematics' embedded symbol copies, so *Update symbols from library* would undo them:
  - U3 pin 5 (OUT) is set to power output.
  - U5 pin 9 (VDD_RF) is set to power output.
  - U5's hidden pin 16 (GND_DR, stacked on pin 12) is set to passive.

  Fix the same pins in the `External` library too.
- **No-connects:** every unused MCU pin has a no-connect flag.
- **Values:** SI style: `100n`, `4.7u`, `15p`, `10k`, `4.7M`, `470R`, `600R@100MHz`, `470nH`. Capacitors carry hidden `Dielectric` and `Voltage` fields (C0G 50V for RF and crystal parts, X7R 16V for 100n/10n, X5R 10V/16V for bulk). Y1 carries an `MPN` field.
- **LCSC field:** every orderable part carries a hidden `LCSC` field (the LCSC/JLCPCB part number). The Fabrication Toolkit plugin reads it from the footprints, so run *Update PCB from Schematic* after changing one. AE3, J5 and J6 have none (PCB features). The ordering BOMs are in `PCB/bom/` (`jlcpcb_bom.csv`, plus Digi-Key and LCSC workbooks); keep them in step with the `LCSC` fields.
- **Layout:** every functional block sits in a titled frame, and each sheet has a filled title block (title, date, rev 0.1, description).

**Design rules** (`Attendance Management System.kicad_dru`):
- **Global minimums:** hole clearance 0.15 mm, annular ring 0.2 mm, hole-to-hole 1 mm, courtyard clearance 0.1 mm, connection width 0.15 mm, and at least 4 thermal-relief spokes.
- **Exceptions:** U2's MSOP-10 pad-to-pad clearance (0.15 mm), and AE3's coil crossover, where hole clearance is ignored.

**Battery divider:** R7/R8 put the PB7 PVD trip at about 1.2 V ÷ 0.365 ≈ 3.3 V, which matches `APP_BATT_CUTOFF_MV`. The firmware uses the same 4.7 M / 2.7 M values. The PVD itself is off in polling mode (`BSP_ENABLE_BATTERY_PVD`); the ADC is sampled instead.

**Open issues:**
- **Firmware limitations found in review (2026-10-06)** are listed under "Known limitations" in `Firmware/docs/ARCHITECTURE.md`: back-to-back lectures within 6 h without a new session (over USB or a 2-5 s button hold) lose returning students, a button lecture can be started by accident, card IDs in the marker range are logged as markers, the marker table caps at 768 (moot when the app clears the log at each lecture), and some editors cannot save a large `SETTINGS.CSV`.
- **The antenna isn't on the board.** Run *Update PCB from Schematic* so AE3 gets `Snapeda:NFC_Loop_40x30_3T`, place it in the antenna rule area, and route its feed to R21/R22. Then tune C16–C19, R15 and the RX divider against the coil's measured L, R and C.
- **The charge current is too high for USB.** R6 = 1 kΩ sets 1 A, more than a USB-C sink with plain 5.1 kΩ Rd may draw (500 mA) and more than the MSOP-10 MCP73833 can dissipate. Use R6 ≥ 2 kΩ.
- **The PN532 header sits close to the antenna.** J7 is just under the antenna area, so a module plugged in there may detune the ST25R3916 loop. Its VCC is on `BAT+`, which is fine only if the module makes its own 3.3 V I/O rail.
- **The `.ioc` lacks PA15 (`PN532_NSS`) and PB6 (`PN532_IRQ`).**
- **The RX signal is about 6× too weak.** On the bench the reader's amplitude measurement read 30 counts (13.02 mVpp each, so ~0.39 Vpp on RFI) where DS12484 recommends 2.5 Vpp (~190 counts) in reader mode. The C37/C38 and C15/C39 dividers (10 pF over 150 pF, ~1/16) cut too much; try 15–33 pF for C38/C39 and check `dbg_nfc_amplitude` with no card present, staying below 230 (the 3 Vpp limit).
- **No watchdog.** Before enabling the IWDG, clear the `IWDG_STDBY` option bit: by default the IWDG keeps running in Standby and would reset the unit back on.

## On-flash and USB formats

Tests, provisioning tools and devices already in use all depend on these formats, so change them deliberately. The layout lives in `App/Inc/nv_layout.h`.

The device is a plain logger: it stores `{card ID, time stamp}` and no names, and keeps no list of registered cards. Every new card gets green and a short buzz (`FB_ACCEPTED`). Who a card belongs to, and whether it is registered at all, is decided only by the PC app from its database. (Firmware up to 2026-10 kept a card list and showed red for unknown cards; that code is gone.)

- **Linker:** the MCU is the 128 kB STM32L432KBU6 (the bench unit's flash-size word at `0x1FFF75E0` reads 128, checked 2026-10-07), so code and data share its 64 pages of 2 kB. `STM32L432KBUX_FLASH.ld` gives `FLASH` the first 72 kB (pages 0-35) and a separate `NVDATA` region the last 56 kB (pages 36-63, from `0x08012000`), so an image that grows too large fails to link instead of overwriting the log. `ASSERT`s in the script and `_Static_assert`s in `bsp_flash.c` keep the script, `BSP_FLASH_BASE` / `BSP_FLASH_SIZE` / `BSP_FLASH_FIRST_PAGE` (`bsp_board.h`) and `NV_REGION_BYTES` (`nv_layout.h`) in step. The image is about 60 kB at -Og (the Makefile and the CubeIDE Debug configuration) and 50 kB at -Os (Release); -O0 (97 kB) does not fit, so don't switch the Debug configuration back to it. Region pages, counted from `0x08012000`:
  - Page 0 holds the config (`nv_config_t`: magic `"CAS1"`, `format_version` 4, `device_id`; `old_card_count` / `old_card_crc32` are written 0 and ignored), read and written by `device_cfg.c`. An earlier format (1 to 3) reads as no configuration.
  - Pages 1-27 hold the attendance log: 27 x 254 = 6 858 records.
  - Firmware for the old 256 kB layout kept its data at `0x08020000`, outside the KB's specified flash. This layout reads none of it, so before flashing a unit that ran it, import its log with the app; set its device ID again afterwards. A reflash can leave old code in the region: that is no valid config (no magic) and no valid log page, and `log_init()` erases such pages.
- **Record:** 8 bytes, `{student_id, stamp}` (the field now holds the card ID), where `stamp` is seconds since 2000-01-01. That is exactly one flash double-word, so a record is never read, modified and rewritten. The record holds no name.
- **Log pages:** each page has a header with a monotonic sequence number, 254 record slots, and a footer with the count and a CRC-16. `log_init()` adopts an unsealed page and keeps appending to it, after a power loss or an ordinary power-off. Pages are sealed only when they fill; sealing a part-filled page wastes its remaining slots. A full log refuses new records unless `APP_LOG_WRAP_WHEN_FULL` is set.
- **RAM buffer:** records stage in RAM (`APP_RAM_RECORDS`) and are flushed to flash at 80 % full, 5 s after the last scan, on USB attach and before power-off. The record count is latched when USB attaches. The reader stays on during a USB session once a host has enumerated (not while it is still deciding whether VBUS is a charger), but a card read then is not logged: it goes to `LASTCARD.TXT` (`enrol_card()`, `APP_SCAN_ENROLLED`, green and a buzz) for the PC app's tap-to-register. VBUS that doesn't enumerate within 5 s is treated as a charger, and scanning carries on. A host eject (SCSI START STOP UNIT with START = 0, latched by the `DataOut` wrapper in `bsp_usb.c` as `plat_usb_ejected()`, acted on after `APP_USB_EJECT_GRACE_MS`) or a short button press ends the USB session the same way: settings applied, reader on, cable still in; `usb_hold_off` keeps the drive away until VBUS drops, or until a double press (`BTN_DOUBLE`, two taps within `APP_BTN_DOUBLE_MS`) brings it back (`usb_attach()`); the PC cannot reconnect it, so the app's Connect button asks for the double press. A 5 s hold applies the settings before switching off; a 2-5 s hold ends the USB session like a short press. While VBUS is present the 3-minute idle switch-off is suspended.
- **Card ID:** the 32-bit `student_id` is the UID read big-endian (`0A F4 1A 9E` → `0x0AF41A9E`, `0183769758` in the CSV). 7- and 10-byte UIDs keep their last four bytes (`card_id_from_uid()`).
- **Sessions:** a lecture is a marker in the log: a header record `{0xFFFFFFF0 | n, start}` and `n` text records `{0xFFFFFFD0, 4 bytes}` holding `module NUL lecture NUL` (module at most 24 bytes, lecture 32). Card IDs from `0xFFFFFF00` (`NV_ID_RESERVED_MIN`) up are reserved and are never card IDs. The host starts one by editing `#MODULE` / `#LECTURE` (or adding `#NEWSESSION`) in `SETTINGS.CSV`; `usbs_end()` reports it and `start_session()` in `app_fsm.c` writes the marker once USB has stopped. **The button starts one too:** hold past `APP_BTN_LONG_MS` (2 s: `BTN_HOLD`, a 60 ms buzz, `FB_HOLD`) and release before `APP_BTN_OFF_MS` (5 s: `BTN_OFF`, power off, no lecture); the release (`BTN_LONG`) runs `new_lecture()`, which keeps the newest marker's module (`sess_latest()`) and numbers the name on (`sess_next_name()`: `Lecture 4` -> `Lecture 5`, no number -> ` 2`, empty log -> `Lecture 1` with no module), then plays `FB_LECTURE` (green, three short buzzes). At attach `usb_storage.c` scans the log once into a table of up to 768 markers (SRAM2) to hide markers from the CSV; a torn marker claims only the text records that exist. The newest marker's names and start time are shown on `STATUS.TXT`, and every marker header is a row of `LECTURES.CSV`.
- **Duplicates:** `dedup.c` (10 s from the tap that counted, RAM; a retry does not restart it, and `start_session()` clears it, so the last card of one lecture counts at once in the next) plus `sess_card_seen()` in `session.c` (a card already in the current lecture, or within `APP_SESSION_MAX_AGE_S` = 6 h when none, read from the flash log so it survives Standby). A duplicate buzzes twice and records nothing. Every other card is recorded, with green and a short buzz (`FB_ACCEPTED`).
- **USB:** the device shows a small FAT12 volume, sized at each attach to fit its contents:
  - `ATTEND.CSV`, read-only, generated on demand and stored nowhere. Rows are a fixed 32 bytes, header included: `DATE,TIME,CARD_ID` (card ID zero padded to 10 digits), then CRLF. Sixteen rows fill a 512-byte sector exactly. Keep the row width a divisor of 512. Session markers in the log are not rows.
  - `SETTINGS.CSV`, read/write, rendered as text into a 14 kB RAM window (`SETF_MAX_BYTES` = 28 x 512). Directives, one per line: `#TIME,YYYY-MM-DD HH:MM[:SS]` (sets the RTC only if changed), `#MODULE`, `#LECTURE`, `#NEWSESSION`, `#CLEARLOG` (erase the whole log, then write any new session marker; the app sends it with a lecture start only after importing every row), and `#DEVICE` (device ID). Any other `#` line is a comment (an old app's `#CARDS` included), and lines not starting with `#` are ignored. The host edits it freely; nothing is applied until the session ends (eject, button press, 5 s hold or VBUS drop) and `usbs_end()` validates the whole file (`setf_scan()` in `settings_file.c`, which never touches flash). A refused file changes nothing.
  - `STATUS.TXT`, read-only, one generated sector starting `ATTENDANCE LOGGER`: device ID, clock, `Battery      : 87 % (3950 mV)` (or `unknown`; `batt_percent()`, set by `usbs_set_battery()` at each sample), record count, `Lectures     : N files in the LECTURES folder`, last tap, current lecture and its start time, and what the current `SETTINGS.CSV` would do. It is rendered at every read; the app reads it past the OS cache to keep the battery current.
  - `LASTCARD.TXT`, read-only, one sector rendered at every read: `LAST CARD`, `Taps    : n` (cards read this USB session, 0 at each attach), `Card ID : 0183769758` (or `none yet`), `UID     : 0A F4 1A 9E` (or `-`), space padded, CRLF at 510. `usbs_set_last_card()` updates it from the main loop in a critical section. The app watches Taps (read uncached) for its tap-to-register.
  - `LECTURES\`, a read-only folder generated on demand: one file per marker header in log order, `L001_2026-10-07_14-30.csv` (lecture number, start date and time; 8.3 alias `L001.CSV`, two LFN entries each, `fat12_lfn_entry()`), the same 32-byte rows as `ATTEND.CSV`, dated at the lecture start. Taps before the first marker are `L000_...`, named after the first of them. Numbers count from 1 in log order, so they restart after `#CLEARLOG`. `plan_lecture_files()` lays them out after everything else and drops the oldest if the volume would pass 4084 clusters. Host writes to the folder's sectors (access dates) are accepted and dropped.
  - After an edit is applied or refused, the unit shows it and carries on scanning: green and two buzzes (`FB_SAVED`) or red and three (`FB_REJECTED`).
  - The FAT has 12 sectors per copy (4096 entries; `FAT12_MAX_CLUSTERS` = 4084, the FAT12 limit). A full log (6 858 rows at 32 bytes) needs about 429 clusters for `ATTEND.CSV` and as much again for the lecture files. Root directory at LBA 25, data from LBA 26.
  - `LECTURES.CSV`, read-only, generated from the marker table: 128-byte rows (`csv_lecture_row()`), header `DATE,TIME,MODULE,LECTURE`, then one `YYYY-MM-DD,HH:MM:SS,module,lecture` row per marker header in log order (module may be empty), space padded, CRLF in bytes 126-127, four rows per sector. Stray text records get no row. The Companion app makes one lecture per row.
  - Clusters: 2 = `STATUS.TXT`, 3-30 = the `SETTINGS.CSV` window, 31 = `LASTCARD.TXT`, 32 on = `ATTEND.CSV`, then `LECTURES.CSV` (at most 193 clusters, reserved before `ATTEND.CSV` is clamped), the `LECTURES` directory, then the lecture files. The window is the only free space the host sees, so every host write lands in RAM, is dropped (the folder) or is refused. The FAT (6 kB) and root directory live in RAM and take the host's changes. `usbs_begin()` takes a `const device_cfg_t *` (the device ID).
- **Device ID:** `devcfg_set_device_id()` is the only writer besides the log. It erases page 0, programs it and reads it back; `usb_leave()` in `app_fsm.c` reloads the config before reporting success.
- **RAM cost of the USB volume:** the 14 kB `SETTINGS.CSV` window stays in the main block; the FAT (6 kB), root directory (0.5 kB), session-marker table (4.5 kB) and lecture-file table (3 kB) are placed in the otherwise unused 16 kB SRAM2 with `__attribute__((section(".ram2")))`, which the `.ram2 (NOLOAD)` output section in `STM32L432KBUX_FLASH.ld` maps to `RAM2`. NOLOAD means startup neither copies nor clears it, so only buffers that are fully initialised before use may go there. Re-add that section if CubeMX regenerates the linker script. The ARM build uses about 22.9 kB of the 48 kB main block (46 %), 14 kB of SRAM2 (88 %) and 60.3 kB of the 72 kB code region (84 %). Check `make` memory usage before adding more RAM users.

## Companion (`Companion/`)

A Python desktop app with one window, `attendance_qt.py` (PySide6), run on the PC the device is plugged into. There is no Tk window, no browser version and no automated test suite. The window uses Fusion style plus one style sheet (`style_sheet()`), sidebar pages, a menu bar and a status bar; device scanning and every write to the device run on a `Worker` thread whose results a `QTimer` drains, so the window never blocks on drive I/O. The rules the window shows (`suggest_title`, `lecture_module`, `banner_list`, `device_summary`, `present_students`, `lecture_csv`, `battery_level`, `TapWatch`, `ConnectWait`, `InstanceLock`, the confirmation wording, `export_file`) live in `app_helpers.py`, which imports no GUI toolkit. The device area has a phone-style battery icon (`BatteryIcon`, painted with QPainter: fill and colour from `battery_level()`, percentage beside it, millivolts in the tooltip), **Connect** (reads the device now; if it is not there, `ConnectWait` asks for a replug or a double press of the device's button and polls every second for 30 s) and **Eject** (`App.eject()`). The Device menu also has **Set device time**, **Clear device records** (`App.clear_device()`: `import_everything()` first, then `#CLEARLOG` and eject; refuses if anything was unreadable) and **Erase device without saving…** (`App.erase_device()`, after typing ERASE). **Clear all records on this computer…** (`App.clear_records()`, after typing CLEAR) takes a time-stamped backup (`snapshot_backup()`), deletes every lecture and tap (`Database.clear_attendance()`, keeping students, modules and enrolments) and can erase the device too. Lecture lists and File → Export (all taps, the student list) save as CSV or PDF; tables go through `report_pages.table_pdf()`, a standard-library PDF writer, so no browser is needed (the richer reports still use headless Chrome/Edge when there is one and fall back to it otherwise). A lock file in the data folder allows one window per database. Every action is a function in `attendance_app.py` (`App.start_lecture`, `set_clock_and_eject`, `clear_device`, `erase_device`, `clear_records`, `last_card`, `eject`, `set_device_id`, and module-level `import_taps`, `edit_lecture`, `save_module` and the `*_export` functions).

`attendance_app.py` finds the drive (it holds `ATTEND.CSV`, `SETTINGS.CSV` and a `STATUS.TXT` starting `ATTENDANCE LOGGER`; extra files and the `LECTURES` folder are ignored), reads `ATTEND.CSV`, `LECTURES.CSV`, `STATUS.TXT` and `LASTCARD.TXT`, and writes only `SETTINGS.CSV`. The device regenerates `STATUS.TXT` and `LASTCARD.TXT` at every read, but the OS caches file contents, so those two are read with `read_uncached()` (Linux `O_DIRECT`, falling back to `posix_fadvise(DONTNEED)`; macOS `F_NOCACHE`; Windows `FILE_FLAG_NO_BUFFERING` with a `VirtualAlloc` buffer; a plain read if all else fails). The students, modules, lectures and taps live in a SQLite database at `~/AttendanceLogger/attendance.db` (`attendance_db.py`, with a dated backup each day, last 14 kept). Registration is the app's alone: the device keeps no card list, so the app never sends one (no `#CARDS`), and a tap whose card no student owns shows as an unregistered card. **Tap to register:** with the device plugged in, *Tap a card…* on the Students page (or *Tap card on device…* in the student dialog) opens `TapDialog`, which polls `App.last_card()` (`parse_last_card()`) every 500 ms on the worker thread and takes the card when `Taps` goes up (`TapWatch`); a card another student owns is refused, and `Database.change_card()` moves an existing student, their modules and taps to the new card. The battery percentage from `STATUS.TXT` (`parse_status()` returns `battery_percent` and `battery_mv`) is shown as a coloured chip while the device is connected. Taps are matched to lectures by time window, using the device's own start times: every row of `LECTURES.CSV` (`parse_lectures()`, `Database.take_device_lectures()`) confirms a lecture the app started or is adopted as a new one, so lectures started from the button each get their taps; a lecture with no module goes under `UNASSIGNED`, and a lecture deleted in the app is not adopted again (`adopted_since`). Taps from before the device's first lecture (its `L000` file) are filed under a "Lecture 0" in `UNASSIGNED` (`Database.take_lecture_zero()`, after `take_device_lectures()`), from the first of them to the first lecture start, or stretching with new taps when the device has no lecture; it is made once per start time (`lecture0_start` in `kv`), so one deleted in the app stays deleted. Older firmware without the file falls back to the newest lecture on `STATUS.TXT`. `App.start_lecture()` first reads every row of `ATTEND.CSV` into the database (`import_everything()`, which requires the row count to match `STATUS.TXT` and every `LECTURES.CSV` row to parse), and only then adds `#CLEARLOG`; after writing it ejects the drive (`eject_drive()`, which returns (worked, reason) and keeps the reason in `App.last_eject_error`: Windows lock/dismount/`IOCTL_STORAGE_EJECT_MEDIA`; macOS `diskutil eject`; Linux `os.sync()`, `udisksctl unmount` retried while Nautilus or tracker hold the drive, then `gio mount --eject`, then a forced unmount, then `udisksctl power-off` or, if polkit refuses it, UDisks2 `Drive.Eject` over `gdbus`) so the lecture starts with the cable in. Reports export as CSV and as PDF (`report_pages.py`, printed by headless Chrome or Edge; Print opens the report as a local HTML file in the browser). `python attendance_qt.py --demo` runs on made-up data, including a fake device with `LASTCARD.TXT` and a `LECTURES` folder, and deletes it on exit. Anything that changes `SETTINGS.CSV` or the `ATTEND.CSV` / `LECTURES.CSV` / `STATUS.TXT` / `LASTCARD.TXT` layout must keep `attendance_db.py` and `Firmware/App/Src/usb_storage.c` / `settings_file.c` in step; with no compat tests left, check by dumping a volume (`Tests/vol_image`) and pointing the app at it.
