# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository layout

Two independent halves of one product, a battery-powered RFID attendance logger that shows its log to a PC as a read-only USB drive holding a CSV file. The firmware was written for 125 kHz EM4100 tags, but the hardware is moving to an ST25R3916 13.56 MHz NFC reader (see the pin map section):

- `Firmware/` is for the **STM32L432KCU6** (Cortex-M4F). It is an STM32CubeIDE project and also has a standalone Makefile.
- `PCB/` is a KiCad 10 project. The root sheet `Attendance Management System.kicad_sch` has three hierarchical sheets: `power.kicad_sch`, `mcu.kicad_sch` and `rfid.kicad_sch`. These are S-expression files that KiCad writes. Don't hand-edit them unless asked. `.history/` and `*.lck` are generated by KiCad and gitignored.

`Firmware/docs/ARCHITECTURE.md` is the design document. It covers the power modes, data formats, the EM4100 decoder, which part of the code handles each step of the flow chart, and board requirements. Read it before any non-trivial firmware change.

## Commands

Run these from `Firmware/`:

```sh
make test    # builds and runs the host tests for Level 2 (plain cc, no ARM toolchain needed)
make         # cross-compiles to build/card-attendance.{elf,hex,bin} and prints memory usage
make clean   # removes build/ and the test binary
```

- `make` uses the GCC that ships with STM32CubeIDE under `/opt/st/stm32cubeide_*/…/tools/bin` when one is installed. Otherwise it falls back to `arm-none-eabi-` on `PATH`.
- The Makefile has no flash or debug target. Flashing and debugging go through STM32CubeIDE. Its build output goes to `Debug/`, which is gitignored.
- All tests build into one binary, `Tests/run_tests`. Each test group is a `test_*()` function called from `main()` in `Tests/test_main.c`. There's no command-line filter, so to run a single group, comment out the other calls in `main()`. The `CHECK()` macro prints `FAIL file:line` for each failure, and the binary exits non-zero if any check fails.
- Warnings are the only lint. `App/` gets extra flags in the cross build (`-Wconversion -Wsign-conversion -Wshadow -Wundef`). The host build is stricter still (`-std=c11 -Wpedantic`, where the cross build uses gnu11), so `App/` code must compile warning-free under both.

Run these from `PCB/` with `kicad-cli` (KiCad 10). Write the reports outside the repo:

```sh
kicad-cli sch export netlist --format kicadsexpr "Attendance Management System.kicad_sch" -o /tmp/ams.net
kicad-cli sch export bom "Attendance Management System.kicad_sch" -o /tmp/ams-bom.csv
kicad-cli sch erc "Attendance Management System.kicad_sch" -o /tmp/erc.rpt
kicad-cli pcb drc "Attendance Management System.kicad_pcb" --schematic-parity -o /tmp/drc.rpt
```

The netlist is the quickest way to see which pin is on which net. The `.kicad_sch` files are hard to read directly.

## Firmware architecture: "Level 2 decides, Level 1 acts"

- **`App/` (Level 2)** holds all the logic and arithmetic. It must include no HAL, CMSIS, vendor or register headers, and it compiles and runs on a workstation. If a host test build ever needs an STM32 header, the layering is broken.
- **`Bsp/` (Level 1)** holds the HAL drivers. They implement `App/Inc/platform_if.h`, the contract that Level 2 declares. Level 1 hands up only raw values (ADC counts together with `VREFINT_CAL`, capture timer ticks, RTC calendar fields, 512-byte sector requests) and makes no decisions. All conversion happens in `App/` (`battery.c`, `em4100.c`, `timeutil.c`, `usb_storage.c`).
- **Event flow:** the only Level 2 symbol that Level 1 may call is `app_event_post()`, from interrupt context. An ISR acknowledges its interrupt and posts an event, nothing else. The main loop runs `bsp_init()`, then `app_init()`, then repeats `app_task()`. Each `app_task()` call pops one event from `app_events.c` and runs the state machine in `app_fsm.c`, which sleeps when the queue is empty.
- **Deciding where a constant goes:** policy values go in `App/Inc/app_config.h`. Hardware facts such as pins, timer instances, clocks and antenna parameters go in `Bsp/Inc/bsp_board.h`, which also holds the full pin map.
- **Adding a platform function** takes three steps: declare it in `platform_if.h`, implement it in `Bsp/Src/`, and add a stub to `Tests/host_platform.c`. The stub is required because the host build compiles every `App/Src/*.c`, `app_fsm.c` included, so a missing stub fails at link time. The stub platform backs flash with RAM and can inject write failures (`host_write_failures`).
- Level 2 modules own no hidden static buffers when they can avoid it. For example, the EM4100 decoder takes a workspace supplied by its caller.

### Low-power rules

- Nothing blocks. Don't use `HAL_Delay` or busy-waits in app code. Feedback patterns are tables of (output mask, duration) pairs, stepped by the one-shot timer on LPTIM2.
- Any timer that must keep running in Stop 2 has to run from the LSE: the RTC, LPTIM1 (the 3-minute inactivity timer) or LPTIM2 (short one-shot timers). A `TIMx` clocked from PCLK stops in Stop 2. The card read is the one exception: it uses Sleep mode because TIM2 capture over DMA must keep running.
- `plat_sleep_idle()` and `plat_sleep_light()` take an "am I still idle?" predicate and re-test it with interrupts masked just before WFI. That check closes the race between the queue check and going to sleep, so keep it.
- The core runs at 4 MHz from MSI with the PLL off. USB sessions raise it to 24 MHz, with HSI48 trimmed by the CRS (the board has no USB crystal).

## MCU pin map (STM32L432KCUx, UFQFPN32)

The card reader is being changed from a discrete 125 kHz EM4100 front end to an **ST25R3916** 13.56 MHz NFC reader on SPI1. The table below comes from `Firmware/Card Attendance System.ioc`, which was updated for the ST25R3916 on 2026-09-25. The rest of the firmware hasn't caught up yet:

- `Bsp/Inc/bsp_board.h`, `bsp_rf.c`, `bsp_gpio.c` and `em4100.c` still drive the old pins: TIM1 carrier on PA8, TIM2 capture on PA1, RF load switch on PA5, touch IC on PA6, PA10 and PB1.
- Regenerating from the `.ioc` comments out `HAL_TIM_MODULE_ENABLED`, so `bsp_rf.c` stops compiling until it is ported.

All 18 used pins are locked in CubeMX.

- **SPI1 must stay in mode 1** (CPOL 0, CPHA 1), 8-bit, MSB first, with software NSS. The ST25R3916 needs BSS held low for a whole multi-byte transaction. The STM32's hardware NSS can't do that: it either stays low as long as SPI is enabled, or, with NSSP, pulses between bytes (and NSSP is ignored when CPHA is 1). The ST25R3916's limit is 10 MHz. The `.ioc` uses /16, which gives 5 MHz at its 80 MHz SYSCLK, so the BSP has to pick its own prescaler for the clock it actually runs at.
- **Internal channels also enabled:** `ADC1_Vref_Input` (VREFINT), LPTIM1 and LPTIM2 counting their internal clock, the RTC calendar, and SysTick.
- **Other pins:** PA1, PA5, PA6, PA8 and PA10 are spare. The schematic uses PA15 (`PN532_NSS`) and PB6 (`PN532_IRQ`) for the PN532 backup header, but they aren't in the `.ioc` yet. `bsp_gpio.c` first sets every pin to analog, the lowest-leakage state, and then configures only the pins it uses. PH3/BOOT0 is strapped low.
- **Card detection** moves to the ST25R3916's own low-power wake-up. The RFID sheet has CSI/CSO capacitive-sensor pads and no separate touch IC.
- **CubeMX ignores some `.ioc` keys.** Headless `config load` reports them as invalid parameters and falls back to the defaults. They include `RCC.Lptim1ClockSelection`, `Lptim2ClockSelection`, `UsbClockSelection` and `AdcClockSelection`, whose correct names are `LPTIM1CLockSelection`, `LPTIM2CLockSelection`, `CK48CLockSelection` and `ADCCLockSelection`. Also ignored: `LPTIMx.Prescaler`, `RTC.Hour_Format`, `USB.VirtualMode`, and the value of `ADC1.CommonPathInternal`. As a result, CubeMX runs LPTIM1/2 from PCLK and USB from PLLSAI1, and the BSP reprograms both at run time. `stop_unused_oscillators()` in `bsp_clock.c` stops the main PLL and HSI48, but not PLLSAI1.
- **Checking an `.ioc` edit without the GUI:** run headless CubeMX on a scratch copy. The generator is `java -jar …/com.st.stm32cube.common.mx_*/STM32CubeMX.jar -q script.txt`, using the JRE bundled under `…/com.st.stm32cube.ide.jre.*/jre/bin/java`. The script runs `config load`, `project toolchain "STM32CubeIDE"`, `project path`, `project name`, then `project generate`. It needs `~/STM32Cube/Repository/STM32Cube_FW_L4_V1.18.2`. Headless mode rewrites `TargetToolchain` and `UnderRoot` in the saved `.ioc`, so don't copy that file back.
- **Two sets of pin macros:** CubeMX generates `*_Pin` / `*_GPIO_Port` in `Core/Inc/main.h`, but the BSP uses its own `PIN_*` / `PORT_*` from `bsp_board.h`. Moving a pin means updating the `.ioc` (then regenerating), `bsp_board.h`, and `PCB/mcu.kicad_sch`.

## PCB (`PCB/`, KiCad 10)

The board is a two-layer, 1.6 mm design. The only net class is the default one: 0.2 mm tracks, 0.2 mm clearance, and 0.6 mm vias with 0.3 mm drills. The root sheet holds three sub-sheets: Power, MCU and RFID.
- Power and MCU are joined by the `D+` and `D-` hierarchical labels.
- RFID connects to the MCU through `NFC_SCK`, `NFC_MISO`, `NFC_MOSI`, `NFC_NSS` and `NFC_IRQ`.

**Library dependencies:** two parts don't come from the stock KiCad libraries, and the project has no `sym-lib-table` or `fp-lib-table`:
- **U3:** its symbol and footprint (`External:TPS7A0233PDBVR`, `External:SOT23_DBV_TEX-L`) come from a SnapEDA library called `External`. It is in the user's global KiCad library tables (`~/Documents/kicad/external_libs/`), not in the repo, so a fresh clone can't resolve U3.
- **U5 (ST25R3916):** its symbol and footprint (`External:QFN50P500X500X100-33N`) come from the same `External` library. ERC gives a `lib_symbol_mismatch` warning, because the copy embedded in the schematic differs from the library's.

Every other part comes from the stock KiCad libraries.

### `rfid.kicad_sch`

- **U5:** ST25R3916-AQWT (QFN-32), in SPI mode because I2C_EN is tied to GND. It was U4 before re-annotation.
- **Supplies:** a single power symbol, `#PWR050`, feeds the `DC2` net, which carries VDD_IO, VDD_TX, R12 (the BSS pull-up), C11, C21 and C25, plus VDD through FB2 (a ferrite bead, 600 Ω at 100 MHz). That symbol was changed from `+3V3` to `BAT+` on 2026-09-25, so all of these now run from the battery. There is no load switch, so the reader is always powered. See the open issues about VDD_IO.
- **Decoupling:** the internal regulator pins (VDD_A, VDD_D, VDD_AM, VDD_RF/VDD_DR, AGDC) each have 100 nF plus 1–2.2 µF.
- **Crystal:** Y1 (ABM8-27.120MHZ, 3225 4-pad) on XTI/XTO, with C9 and C10 (15 pF).
- **Antenna path:** RFO1/RFO2 go through an EMC filter (L3/L4, 470 nH in 0402, with C12/C13, 150 pF), then the matching network (C16–C19) to the antenna AE1/AE2. R15 (1.5 kΩ) sits across the antenna. RFI1/RFI2 take the receive signal back through C14/C15 (100 pF) and R13/R14 (1 kΩ).
- **Capacitive sensor:** J6 (on CSI) and J5 (on CSO) are 1×2 mm SMD solder pads for the electrode used by the chip's capacitive wake-up.
- **Unused pins:** MCU_CLK, EXT_LM, AAT_A and AAT_B are not connected.

### `power.kicad_sch`

- **USB input:** J1 is a USB-C receptacle (GCT USB4110, USB 2.0 only). It is set up as a sink with 5.1 kΩ CC pull-downs (R1, R2), and VBUS becomes `+5V`. SBU1 and SBU2 are not connected.
- **Charger:** U2 is an MCP73833 Li-ion charger, fed from `+5V` and charging `BAT+`.
  - R6 (1 kΩ) on PROG sets about 1 A of charge current (I_REG = 1000 V / R_PROG).
  - TH1, an NTC thermistor, is on THERM.
  - Status LEDs: D1 (red) on STAT1, D2 (green) on STAT2 and D3 (green) on PG, each through 470 Ω. They are powered from `+5V`, so they only light while USB is plugged in.
- **Battery:** J2 is a 2-pin JST-XA connector on `BAT+`.
- **3.3 V supply:** U3 is a TPS7A0233 3.3 V LDO running from `BAT+` to `+3V3`. Its EN is tied to `BAT+`, so it is always on.
- **Bulk capacitors (0805):**
  - C35 (4.7 µF) on `+5V`. Keep the total on VBUS at or below USB's 10 µF limit.
  - C36 (10 µF) on `BAT+`, covering the charger output, the LDO input and the motor.
  - `+3V3` has C2 (4.7 µF) plus the 100 nF decouplers C1 and C3. C21 moved to `BAT+` with the reader supply.

### `mcu.kicad_sch`

- **U1:** STM32L432KCUx.
- **Decoupling:** C1 and C3 (100 nF) plus C2 (4.7 µF) on `+3V3`. VDDA is fed through ferrite bead FB1, with C4 (10 nF) and C5 (1 µF).
- **Crystal:** Y2 (32.768 kHz) with C6 and C7 (4.3 pF).
- **Reset and boot:** NRST has C8 (100 nF) and the SW1 reset button. BOOT0 (PH3) has R7 (10 kΩ) pulling it down and the SW2 button pulling it to `+3V3`.
- **Debug:** J3 is a 4-pin SWD header: 3V3, SWDIO, SWCLK and GND. It has no NRST pin.
- **LEDs:** D6 (green) on PA2 and D5 (red) on PA3, each through 470 Ω to GND. They are active high, which matches the firmware.
- **Vibration motor:** the motor plugs into J4, between `BAT+` and the drain of Q1, an AO3400A low-side N-MOSFET. Q1's gate is driven by PA4 (`VIB_EN`) and pulled down by R11 (10 kΩ). D4, an SS14 flyback diode, sits across J4 with its cathode on `BAT+`.
- **Button:** SW3 (`KEY`) switches to GND, with R8 (10 kΩ) pulling it up to `+3V3`.
- **Battery sense:** R16 (4.7 MΩ, from `BAT+`) over R17 (2.7 MΩ), with C34 (100 nF) across R17, feeds both PA7 and PB7.
- **VBUS sense:** R18 and R19 (4.7 MΩ each) divide `+5V` down to PA9.
- **PN532 backup header:** J7 is a 1×8 2.54 mm socket for a PN532 breakout, pinned for the Elechouse V3's SPI header with the module's DIP switches set to SPI.
  - **Pinout:** 1 SCK, 2 MISO, 3 MOSI, 4 SS, 5 VCC (now `BAT+`), 6 GND, 7 IRQ. Pin 8 (RSTO) has a no-connect flag.
  - **Shared:** SCK, MISO and MOSI, with U5.
  - **Separate:** the PN532 has its own chip-select, `PN532_NSS` on PA15, pulled up by R20 (10 kΩ), and its own IRQ, `PN532_IRQ` on PB6. The two readers' IRQ outputs have opposite polarity and are both push-pull, and a faulty U5 would still drive MISO, so neither line can be shared.
  - **Firmware:** the PN532 uses SPI mode 0, LSB first, at up to 5 MHz, and its IRQ is active low. Reconfigure SPI1 whenever you switch readers. PB6 is EXTI6, which shares the `EXTI9_5_IRQn` vector with PA9 (VBUS).
  - **Power:** VCC is on `BAT+`, so the module's RF current bypasses the 200 mA LDO. This only works if the module makes its own 3.3 V I/O rail; see the open issues.

## CubeMX-generated code (`Core/`, `Drivers/`, `Middlewares/`)

- Edit `Core/` only inside `USER CODE BEGIN/END` blocks. Treat `Drivers/` and `Middlewares/` as vendor code.
- Peripheral IRQ handlers live in `Bsp/Src/bsp_isr.c`, **not** in `stm32l4xx_it.c`. Their code generation is switched off in the `.ioc`.
- At run time, `Bsp/` reprograms every peripheral after the `MX_*_Init()` calls, so the settings in `Card Attendance System.ioc` only mirror the BSP and never override it. When you change a peripheral, change the BSP and keep the `.ioc` in sync.
- **After regenerating from the `.ioc`**, fix two things:
  1. CubeMX deletes `Middlewares/ST/STM32_USB_Device_Library/` and drops `Middlewares` from the source folders in `.cproject`. Restore the library from STM32Cube_FW_L4 (Core and Class/MSC only, without the `*_template.c` files) and add the source-folder entry back.
  2. CubeMX re-emits `HAL_PCD_MspInit` and `HAL_PCD_MspDeInit` into `Core/Src/stm32l4xx_hal_msp.c`, where they collide with the versions in `Bsp/Src/bsp_usb.c`. Delete the generated pair. The BSP version is the correct one.

## On-flash and USB formats

Tests, provisioning tools and devices already in use all depend on these formats, so change them deliberately. The layout lives in `App/Inc/nv_layout.h`.

- **Linker:** the `FLASH` region is cut to 128 kB. The top 128 kB, from `0x08020000`, is a separate `NVDATA` region, so an image that grows too large fails to link instead of overwriting the log.
  - Page 0 holds the config (`nv_config_t`: magic `"CAS1"`, count, CRC-32, device ID).
  - Pages 1–8 hold up to 4096 sorted 32-bit student IDs, searched in place.
  - Pages 9–63 hold the attendance log.
- **Record:** 8 bytes, `{student_id, stamp}`, where `stamp` is seconds since 2000-01-01. That is exactly one flash double-word, so a record is never read, modified and rewritten.
- **Log pages:** each page has a header with a monotonic sequence number, 254 record slots, and a footer with the count and a CRC-16. After a power loss, `log_init()` adopts an unsealed page and keeps appending to it. A full log refuses new records unless `APP_LOG_WRAP_WHEN_FULL` is set.
- **RAM buffer:** records stage in RAM (`APP_RAM_RECORDS`) and are flushed to flash at 80 % full. The record count is latched when USB attaches, and scans taken during a USB session stay in RAM until the next attach.
- **USB:** the device shows a 1 MB read-only FAT12 volume holding a single `ATTEND.CSV`. Every sector is generated on demand and nothing is stored. CSV rows are a fixed 32 bytes, header included, so each 512-byte sector holds exactly 16 rows. Keep the row width a divisor of 512.
- **Student list:** the firmware never writes it; it's provisioned from outside. `provision_students()` in `Tests/test_main.c` shows the exact layout. If the CRC is bad, the whole list is rejected and every card reads as unknown.
